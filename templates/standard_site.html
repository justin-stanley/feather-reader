standard.site

FeatherReader reads standard.site publications, beside your feeds.

Since 0.4.0, a publication written to its author's atproto repo is a subscription here like any RSS feed: same list, same order, same portable record in your own PDS.

What a publication is

standard.site is a lexicon for publishing on atproto. A publication is a site.standard.publication record in the author's own repo — a name and a site URL — and each article is a site.standard.document record in the same repo, naming the publication it belongs to. There is no feed document anywhere: the articles are the records, and they live with the author, not with any platform.

What FeatherReader does with one

FeatherReader reads those two collections directly from the author's PDS, without signing in to anything. It shows each article's title, date, link and a plain-text summary, taken from the document's description or, failing that, its textContent. An article with neither still appears as its title, date and link — the same thing an RSS reader shows for a title-only feed.

It deliberately does not render a document's rich content. That field is not a standard: measured across the publications FeatherReader follows, it carried six different wrappers and twenty-two block types from five publishing platforms, and the set grows with each new platform. The link takes you to the article as its author published it.

A publication subscription is the same community.lexicon.rss.subscription record as a feed, with the publication's at:// URI where a feed URL would be — so it is just as portable, and it exports in your OPML like everything else. Publications are re-read on the same interval as feeds, on their own polling loop, so a slow publication never holds up your RSS. When one author's repo holds several publications you follow, it is read once per round for all of them.

How to subscribe

{% if standard_site %}

Paste the publication's URI into the subscribe form on the manage page, in either spelling:

  • at://did:plc:…/site.standard.publication/… — the DID form
  • at://alice.example.com/site.standard.publication/… — the handle form

A handle is resolved to its DID before the subscription is saved, and only the DID form is stored, because a handle is a mutable name for an account. The first read runs at once, so the articles appear immediately. A publication can also arrive in an OPML import, as the DID form.

{% else %}

This instance isn't accepting new publication subscriptions yet; publications it already follows are still read on every round. The switch is FEATHERREADER_STANDARD_SITE on a self-hosted instance.

{% endif %}

Limits, honestly

  • Summaries, not full articles. The rich content is never rendered, for the reasons above. If a document has neither a description nor textContent, you get the title, date and link only.
  • Public repos only. FeatherReader reads without signing in, so a publication must be readable by anyone. did:plc and did:web authors are supported.
  • Reading only. FeatherReader does not publish, and it does not read or write standard.site's own site.standard.graph.subscription records, so a subscription made in another standard.site client does not appear here on its own.
  • One read has a deadline (30 seconds by default). A publication with thousands of documents could exceed it and fail to update; the largest one followed when this was measured ran to seven pages of twenty-five.
  • An at:// URI that is not a publication is never read. Another collection, a non-canonical spelling or an invalid DID is kept as unsupported rather than retried as a broken feed.
